Developer

Dynamic module SDK.

Write a codec module, drop it in a folder, and it's loaded at runtime. No recompilation. No forking.

Write a module

// my_codec.c → my_codec.dylib #include <cutecontainer/sdk.h> static int my_probe(const uint8_t *h, size_t l) { return l >= 4 && memcmp(h, "MYCC", 4) == 0; } static int my_encode(const uint8_t *in, size_t n, uint8_t **out, size_t *len, const cc_opt *opts) { // your codec here } const cc_module *cc_module_init(void) { static const cc_module m = { .name = "my-codec", .type = CC_TYPE_CUSTOM, .sdk_version = CC_SDK_VERSION, .caps = CC_CAP_ENCODE | CC_CAP_DECODE, .probe = my_probe, .encode = my_encode, .decode = my_decode, .free_buf = free, }; return &m; }

Storage

NVMe native.

When NVMe devices are present, cutecontainer can bypass the filesystem entirely. Direct I/O, computational storage offload, and content-addressable key-value stores — all through standard NVMe commands.

DIO

Direct I/O

Bypass the filesystem for large containers. Aligned reads/writes directly to the NVMe namespace. No page cache overhead, no VFS latency.

CMB

Controller Memory Buffer

Zero-copy GPU↔storage via NVMe CMB. On Linux with GPUDirect Storage, data flows directly from SSD to GPU VRAM without touching system RAM.

CS

Computational Storage

Offload compression and SHA3 hashing to the SSD controller. Data is processed in-place on the drive — never crosses the PCIe bus. cc_nvme_compress() and cc_nvme_hash().

KV

Key-Value Commands

Content-addressable container store using NVMe KV. Key = SHA3-256 hash, Value = container. Instant deduplication. cc_nvme_kv_put/get/exists/delete.

ZNS

Zoned Namespaces

Append-optimized writes for the depo ledger and WAL. Sequential zones eliminate write amplification on QLC/PLC NAND.

RT

Runtime detection

cc_nvme_probe() discovers NVMe devices and their capabilities at runtime. Graceful fallback to standard file I/O when NVMe extensions aren't available.

Performance

Hardware all the way down.

Hand-written assembly for the hot paths. GPU compute for spectral processing. Apple media engine for ProRes. No generic library calls where silicon can do the work.

ASM

aarch64 + x86_64

rANS encode/decode, LZ match finding, AES-256 rounds (AESE/AES-NI), Kyber NTT, Curve25519 field ops, CuteHash ARX, spectral delta/deinterleave. 22 hand-written assembly files.

GPU

Metal + OpenCL

Spectral-to-RGB via CIE 1931 integration. Fused film fold+develop kernel. Both MSL and OpenCL C implementations — same results on any GPU vendor.

HW

Media engine

ProRes encode/decode through Apple Silicon's dedicated hardware block. VTCompressionSession with explicit hardware request. Zero-copy IOSurface from Metal.

PQ

Post-quantum

ML-KEM-768 (Kyber) key encapsulation. 128-bit security even against quantum computers. SHAKE-256 KDF. Constant-time throughout.

x86

SIMD detection

Runtime CPUID probing for AVX2, AVX-512, and AES-NI. The library adapts to whatever your CPU supports — no compile-time flags needed.

0

Zero dependencies

Pure C11. No external libraries. OpenCL and Metal are optional — the library always works with CPU fallback. Cross-compile for any target.

WAL Rail

1,228x faster reads.

A cleartext append-only index at the end of every container. Answer any question about the file without touching the payload. No decrypt. No decompress.

Volumes

Game asset volumes.

Pack thousands of assets into a single .cute file. Mount reads only the manifest + WAL. Individual assets decompress on demand. A writable overlay stores saves, config, and mods.

📦

Build

Add files with per-asset compression, wrap types, and group IDs. The builder writes the manifest + payload + WAL in one pass.

🔍

Mount & query

Mount reads manifest only. Find assets by path, prefix, group, or wrap type — all in-memory, no I/O.

🎮

Overlay

Writable user data alongside the read-only volume. Saves, config overrides, and mods go to the overlay. Original assets are never modified.

🚀

Exec

Volumes can be executable. The master declares entry points per platform. Launch extracts to a sandbox and injects $CUTE_VOLUME, $CUTE_SAVES, $CUTE_MODS.

// build cc_vol_builder *b = cc_vol_builder_create("game.cute"); cc_vol_builder_add_file(b, "textures/hero.png", "art/hero.png", CC_VOL_COMPRESS); cc_vol_builder_add_entry_point(b, CC_PLAT_ANY, CC_INTERP_LUA, "scripts/main.lua", "", CC_EXEC_SANDBOX); cc_vol_builder_finish(b); // mount + load cc_volume *vol = cc_vol_mount("game.cute"); void *tex = cc_vol_load(vol, "textures/hero.png", &len); // overlay (user data) cc_vol_write_overlay(vol, "saves/slot1.sav", save_data, save_len); void *cfg = cc_vol_load_overlay(vol, "config.json", &len); // launch cc_vol_exec(vol);
